## 1. Project Objective & Final Tech Stack

### Objective

**CineBook** is a production-grade movie ticket booking platform built as a learning project to demonstrate:

- High-concurrency seat reservation with race-condition prevention (Redis + DB transactions)
- Real-time seat map synchronization across concurrent users (Socket.IO)
- Decoupled payment processing with idempotency (Razorpay webhook deduplication)
- Modular monolith architecture principles

### Final Tech Stack

| Concern | Technology |
|---|---|
| Frontend | React + Vite + Tailwind CSS |
| Backend | Node.js + Express.js |
| Database | PostgreSQL |
| ORM | Prisma ORM |
| Cache / Locks | Redis (Phase 2) |
| Payments | Razorpay Test Mode (Phase 3) |
| Real-time | Socket.IO (Phase 2) |
| Auth | JWT + bcrypt (Phase 2) |
| Testing | Jest + Supertest + Autocannon |
| Architecture | Modular Monolith |

### Key Design Decisions

#### 1. Monetary Values Stored in Paise (Integer Minor Units)
Storing price as `INT` paise (₹1 = 100 paise) eliminates floating-point rounding errors.
`₹250.00` is stored as `25000`. All arithmetic is exact integer arithmetic.
The client receives the integer and formats display (₹ symbol, decimal) in the UI layer.

#### 2. Two-Phase Concurrency Control (Critical System Design Concept)
The `ShowSeat` unique constraint on `(showId, seatId)` prevents duplicate inventory rows
but does **NOT** prevent two concurrent transactions from both reading `status=AVAILABLE`
and both trying to set `status=BOOKED`. This is the **lost update anomaly**.

**Our solution (Phase 2):**
- **Phase 1 (Redis SETNX):** Atomic Redis key set with 10-minute TTL prevents two users
  from even entering the payment flow for the same seat simultaneously.
- **Phase 2 (DB transaction):** `SELECT ... FOR UPDATE` inside a Prisma transaction confirms
  the hold before committing the permanent `BOOKED` status.

**Why this matters:** This is a classic distributed systems problem. A unique DB constraint
is a necessary but not sufficient condition for correctness under concurrency.

#### 3. app.js vs server.js Separation
`app.js` exports the configured Express app without starting any listeners.
`server.js` imports `app` and calls `server.listen()`.

**Why:** Supertest imports `app` directly and manages its own ephemeral port.
If `server.js` called `listen()` at import time, tests would get EADDRINUSE port conflicts.

#### 4. Fail-Fast Environment Validation
`src/config/env.js` checks all required variables at startup before binding to a port.
A missing `DATABASE_URL` crashes immediately with a clear message rather than throwing
a confusing error on the first DB query.

#### 5. Centralized Error Handler with Prisma Error Translation
All Prisma errors (P2002 unique violation, P2025 not found, P2003 FK violation) are caught
in `errorHandler.js` and converted to meaningful HTTP responses (409, 404, 400).
Stack traces are only included in `development` mode — never in production responses.

#### 6. ProcessedWebhookEvent Table for Idempotency
Payment webhooks from Razorpay can be delivered more than once (network retries).
Before processing any webhook, the server checks `ProcessedWebhookEvent` for the event ID.
If already processed, it returns 200 without re-executing. This is **idempotent webhook handling**.

#### API Endpoints Implemented

| Method | Endpoint | Auth Required | Description |
|---|---|---|---|
| `POST` | `/api/auth/register` (and `/api/v1/auth/register`) | Public | Register new user (enforces `role: USER`, hashes password with bcrypt, returns JWT + safe user) |
| `POST` | `/api/auth/login` (and `/api/v1/auth/login`) | Public | Authenticate user with email and password (returns JWT + safe user) |
| `GET` | `/api/auth/me` (and `/api/v1/auth/me`) | Bearer Token | Retrieve currently authenticated user profile |

#### Security Decisions & System Design Highlights

1. **Bcrypt Password Hashing**: Passwords hashed with 10 salt rounds. Plaintext passwords are never persisted and never returned in API payloads.
2. **JWT Configuration**: Signed with HMAC SHA256 using `JWT_SECRET` and `JWT_EXPIRES_IN` loaded from environment variables (fail-fast validated at server boot).
3. **Privilege Escalation Prevention**: During registration, client requests attempting to set `role: ADMIN` are neutralized; the system unconditionally assigns `role: USER`.
4. **Information Disclosure Prevention**: Login failure returns generic `INVALID_CREDENTIALS` ('Invalid email or password') rather than distinguishing whether the email or password was wrong, mitigating user enumeration attacks.
5. **Safe User Profile Serialization**: The `toSafeUser()` utility strips password hash before responses are dispatched.
6. **Input Normalization & Validation**: Email strings are trimmed and lowercased; strict format regex validation; password minimum length enforced (>= 6 chars).
7. **Stateless Auth Middleware**: The `authenticate` middleware parses the `Authorization: Bearer <token>` header, verifies token validity and expiration, confirms the user still exists in PostgreSQL, and attaches `req.user` and `req.userId` for downstream route handlers.

## 7. Bugs Encountered & Fixes Applied

### Bug 1: Prisma 7.10.0 Configuration Architecture (P1012 & Missing `prisma.config.ts`)
- **Symptom / Context:** In Prisma 7, the `url` property is removed from `datasource db` in `schema.prisma` (throws error `P1012: The datasource property 'url' is no longer supported in schema files`). Prisma 7 moves datasource URLs and migration seeds to the dedicated `prisma.config.ts` file.
- **Root Cause:** Prisma 7 moved CLI migration configuration out of `schema.prisma` into `prisma.config.ts` and transitioned database connectivity to driver adapters.
- **Fix Applied:**
  1. Kept `schema.prisma` datasource clean (`provider = "postgresql"` without inline `url`).
  2. Created `server/prisma.config.ts` using `defineConfig` with `import 'dotenv/config'`, pointing `schema`, `datasource.url`, and `migrations.seed`.
  3. Ran `npx prisma validate` and `npx prisma generate` — both succeed cleanly with exit code 0.

### Bug 2: Jest Configuration Typo in package.json
- **Symptom:** `setupFilesAfterFramework` used instead of official Jest key.
- **Fix Applied:** Updated key to `setupFilesAfterEnv` in `server/package.json`.

### Bug 3: Prisma 7 Driver Adapter Missing at Runtime (`PrismaClientConstructorValidationError`)
- **Symptom:** `PrismaClientConstructorValidationError: PrismaClient requires a driver adapter to connect to your database, but none was provided.` occurred when calling `new PrismaClient()`.
- **Root Cause:** In Prisma 7, direct connections to PostgreSQL without Accelerate require an explicit driver adapter (`@prisma/adapter-pg` along with `pg`).
- **Fix Applied:**
  1. Installed `@prisma/adapter-pg` and `pg`.
  2. Updated `src/config/db.js` to initialize `new PrismaPg({ connectionString: config.databaseUrl })` and supply `adapter` to `new PrismaClient({ adapter })`.
  3. Updated `prisma/seed.js` and `tests/schema.test.js` to utilize `PrismaPg` adapter.
  4. Verified all health and schema tests pass immediately.
